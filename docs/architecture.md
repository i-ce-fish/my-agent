# 设计取舍

## 2026-11-02：首次模型调用采用标准库和单次流式请求

- 选择：使用 `urllib.request` 发送请求，按 SSE 事件边界解析增量回答；配置读取、请求解析和 CLI 分为简单函数。
- 原因：当前只有一次对话需求，与已验证的 curl 请求保持一致，便于观察 `messages → HTTP → delta.content → 终端` 的数据流。
- 暂不引入：OpenAI SDK、Agent 框架、自动重试和会话存储。代价是自行维护 SSE 解析；当前实现只处理此接口的聊天文本流。

## 2026-11-02：结构化提取采用非流式请求与本地校验

- 选择：发送 `response_format.json_schema` 表达契约；正常结束且两个字段通过本地校验后才输出 JSON，不修补、不自动降级或重试。
- 原因：内网接口接受 `strict: true`，但冲突探测实际违反 Schema，因此必须由程序拒绝不合格数据。非流式输出避免下游消费尚未校验的片段。
- 代价：需等待完整结果；手写校验仅覆盖当前两个字段，不能保证语义正确。暂不引入 SDK、校验框架和自动纠错，以便直接观察模型与程序各自提供的保证。
